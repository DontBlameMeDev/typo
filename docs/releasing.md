# Releasing

Releases are built locally with `scripts/release.sh` and published to
[Codeberg releases](https://codeberg.org/DontBlameMe/typo/releases). There is no
CI build.

## One-time setup

The APK signing key identifies the app for Android. Every release must use the
same key, otherwise devices refuse the upgrade and users have to uninstall.
Generate it once and keep a copy somewhere that is not this repository.

```bash
mkdir -p ~/keys
keytool -genkeypair -v -keystore ~/keys/typo.jks -alias typo \
  -keyalg RSA -keysize 4096 -validity 10000
```

Store the password in your password manager. `fj` needs to be logged in
(`fj whoami`) to publish.

## Release

1. Bump `expo.version` and `expo.android.versionCode` in `app.json`. The version
   code must always increase, and `version` must match the tag: `0.2.0` becomes
   tag `v0.2.0`.
2. Optionally write `docs/releases/0.2.0.md` for the release notes.
3. Commit the bump, then run:

```bash
KEYSTORE=~/keys/typo.jks KEYSTORE_PASSWORD=... ./scripts/release.sh
```

The script refuses to run on a dirty tree or when the tag or release already
exists. It builds the web bundles, runs `expo prebuild`, builds an arm64-only
release APK, signs it, prints the SHA-256, and creates the tag and release with
the APK attached.

The Android project under `android/` is generated by `expo prebuild` and is not
committed, so signing and ABI selection live in the script rather than in Gradle
files.

## Notes

- `releases/` and keystores are gitignored. Release notes under `docs/releases/`
  are committed.
- The script refuses to publish an APK whose version code does not match
  `app.json`.
- The APK is signed after Gradle's debug signature, which `apksigner` replaces.
- Emulator builds keep the x86-64 architecture. Only the published APK is
  arm64-only.
